# コード編集時の対象・差分・取り消し設計

Issue #132 P2 の条件付き設計です。現在の主用途は個人自動化です。ここではコード編集を重点用途にした場合の契約を定義します。`/undo` や Git 自動操作はまだ提供していません。

## 対象ファイルを選ぶ

- セッションに workspace の実パスと編集許可した相対パスの一覧を保持する。既存の `readFile` / `writeFile` sandbox に加え、選択したファイルだけを変更できるようにする。
- 実パスで sandbox 内を確認し、`..`、絶対パス、外部へ向く symlink、Git 管理領域を拒否する。移動・削除・新規作成も対象選択に含める。
- 開始時の Git HEAD、index、作業ツリーの状態を把握し、未コミットのユーザー変更を元の状態として保護する。未追跡ファイルも上書きしない。

## 変更を確認する

書き込み意図に task ID、相対パス、変更前の存在有無・内容ハッシュ、変更後ハッシュ、差分、承認 ID を記録する。差分は preview 用と適用用を分離し、画面上の省略を明示する。

承認待ち中の外部編集を検出するため、実行直前に元内容のハッシュを照合する。不一致なら変更を適用せず、最新内容で差分と承認を作り直す。複数ファイルでは途中失敗を隠さず、各パスの適用済み／未適用を記録する。

現行の `writeFile.dryRun` は対象と差分のプレビューを提供するが、完全なパッチや楽観ロックではない。この設計で同じ仕組みを拡張する。

## 取り消す

将来の `/undo <change-id>` は、その変更が書いたファイル内容だけを取り消す。変更前の内容は task ID に関連するローカルの変更記録へ保存する。Git 全体の reset、clean、checkout は使わない。

| 現在の状態 | 取り消しの動作 |
| --- | --- |
| 現在のハッシュが記録した変更後ハッシュと一致 | 元内容を復元し、復元結果を記録する |
| ユーザーや別タスクが再編集した | 競合として停止し、差分を提示する |
| この変更で新規作成し、その後変更されていない | 対象を明示して削除を確認する |
| 元から存在しない／記録が欠けている | 復元可能と推測せず停止する |
| 通知・メール・外部 API・DB 更新 | ファイル undo の対象外。サービス別の補償操作と新しい承認が必要 |

取り消しも新しい副作用として intent と結果を永続化する。クラッシュ時は結果不明を保持し、自動で逆操作を繰り返さない。Git commit 済みの変更は、対象差分を説明して通常の revert を別途検討する。

## 実装時の受入テスト

対象外パス・symlink 脱出の拒否、ユーザー変更保持、承認中の外部編集、複数ファイルの部分失敗、新規ファイルの取り消し、取り消し後の再起動、結果不明の停止、外部送信が undo されないことを検証する。現在の3シナリオの回帰テストとは別に追加する。
