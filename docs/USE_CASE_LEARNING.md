# CopHarness 利用シーン別ラーニングパス

CopHarness は CLI、HTTP API、Discord / LINE Bot、ダッシュボード、スケジューラー、スキル、承認ゲートを組み合わせて使える LLM ハーネスです。機能を個別に試すだけでは全体像を掴みにくいため、このガイドでは「何を実現したいか」から逆引きできる学習コンテンツをまとめます。

## まず覚える全体像

| レイヤー | できること | 最初に触る場所 |
| --- | --- | --- |
| 対話 | CLI、Discord、LINE、HTTP API から LLM と会話する | `npm run cli`、`/api/copilot` |
| 自動化 | cron スケジュールやイベント監視でプロンプトを実行する | `/dashboard` のスケジューラー / ウォッチャー |
| 拡張 | スキルでファイル、検索、通知、計算などを呼び出す | `docs/SKILLS_GUIDE.md`、`/dashboard` のスキル一覧 |
| 運用 | ログ、コスト、トークン、承認待ちを確認する | `/dashboard` のログ / コスト / 承認 |
| 安全性 | 高リスクスキルを承認制にし、API 認証を設定する | `.env.local`、Human-in-the-Loop 設定 |

## ラーニングパス 1: まずは手元で会話する

**目的:** API キーを設定し、LLM との対話が成立することを確認します。

1. `.env.example` を `.env.local` にコピーします。
2. OpenAI、Anthropic、Gemini、Copilot、LM Studio など、利用するプロバイダのキーまたは URL を 1 つ設定します。
3. `npm install` を実行します。
4. `npm run cli` で CLI を起動します。
5. 「このリポジトリの使い方を 3 行で説明して」と入力し、応答を確認します。

**確認ポイント:**
- 起動時に表示される provider / model が期待どおりか。
- タイムアウトする場合は `COPILOT_TIMEOUT_MS` を調整する。
- 同じ環境変数で Web API とダッシュボードも利用できる。

## ラーニングパス 2: Web UI で運用を見える化する

**目的:** ダッシュボードで状態、ログ、スキル、コストを確認します。

1. `npm run dev` を実行します。
2. ブラウザで `http://localhost:3000/dashboard` を開きます。
3. 「プロバイダ状態」で有効なプロバイダを確認します。
4. 「スキル一覧」で利用可能なスキルとリスクレベルを確認します。
5. CLI または API を 1 回実行し、ログやトークン使用量が更新されるか確認します。

**おすすめプロンプト:**

```text
現在時刻を確認し、今日の学習計画を 3 ステップで作ってください。
```

## ラーニングパス 3: 定期タスクを作る

**目的:** 毎日・毎週の定型作業を CopHarness に任せる流れを理解します。

1. `/dashboard` のスケジューラーで「スケジュール追加」を開きます。
2. 名前に「朝の作業計画」、cron に `09:00` を入力します。
3. プロンプトに以下を設定します。

```text
今日の作業候補を、優先度・所要時間・リスクの観点で整理してください。
```

4. 保存後、「今すぐ実行」で動作確認します。
5. 実行ログで結果と失敗時のエラーを確認します。

**応用:** Discord チャンネル ID や LINE ユーザー ID を設定すると、定期実行の結果をチャットに届けられます。

## ラーニングパス 4: スキルでできることを広げる

**目的:** LLM がローカル関数や外部 API を呼び出す流れを試します。

1. `docs/SKILLS_GUIDE.md` でスキル一覧を確認します。
2. 低リスクな `currentDateTime`、`calculator`、`jsonFormat` から試します。
3. ファイルやコマンド実行など副作用があるスキルは、テスト用ディレクトリで実行します。

**おすすめプロンプト:**

```text
calculator を使って、8 時間作業のうち 25 分集中 + 5 分休憩を何セット回せるか計算してください。
```

**安全な試し方:**
- 最初は読み取り専用スキルだけを使う。
- ファイル書き込みやコマンド実行はダミーデータで検証する。
- 高リスクスキルは Human-in-the-Loop を有効化してから運用する。

## ラーニングパス 5: チャットボットとして使う

**目的:** チームや個人のチャットから CopHarness を利用します。

### Discord

1. Discord Developer Portal で Bot を作成します。
2. `DISCORD_BOT_TOKEN` を `.env.local` に設定します。
3. `npm run discord`、または `npm run dev` で Next.js と併用起動します。
4. DM または @メンションで話しかけます。

### LINE

1. LINE Developers Console で Messaging API チャネルを作成します。
2. `LINE_CHANNEL_SECRET` と `LINE_CHANNEL_ACCESS_TOKEN` を設定します。
3. `/api/line` を Webhook URL に設定します。
4. LINE 公式アカウントにメッセージを送って確認します。

**利用例:**
- 毎朝の作業整理 bot。
- 画像付き質問に答える Discord bot。
- LINE から個人メモを要約する bot。

## ラーニングパス 6: 安全に本番運用する

**目的:** 認証、承認、ログ確認を組み合わせ、誤実行や情報漏えいを減らします。

1. `COPHARNESS_API_KEY` を設定し、HTTP API とダッシュボード API を Bearer 認証で保護します。
2. `HIL_ENABLED=true` を設定し、高リスクスキルの承認ゲートを有効化します。
3. `/dashboard` の承認待ち画面で、実行内容を確認してから承認 / 却下します。
4. ログ、コスト、トークン使用量を定期的に確認します。
5. `logs.json` などに機密情報を含めない運用ルールを作ります。

## 実践課題

| 課題 | ゴール | 使う機能 |
| --- | --- | --- |
| 朝会アシスタント | 今日の予定とリスクを毎朝まとめる | スケジューラー、通知 |
| リリース前チェック | チェックリストをプロンプト化して手動実行する | CLI、ダッシュボードログ |
| 調査メモ作成 | Web 検索や URL 取得を使って要点を整理する | スキル、ノート |
| 承認付き自動化 | コマンド実行前に人間が確認する | Human-in-the-Loop、承認画面 |

## つまずいたときの見方

- 応答がない: API キー、モデル名、タイムアウトを確認する。
- Bot が返答しない: トークン、Webhook URL、Discord の Message Content Intent を確認する。
- スキルが使われない: 利用プロバイダがスキルに対応しているか、スキル名が有効か確認する。
- スケジュールが動かない: cron 表記、スケジューラーデーモン、ログのエラーを確認する。
- 本番に出すのが不安: `COPHARNESS_API_KEY` と `HIL_ENABLED` を先に設定する。
